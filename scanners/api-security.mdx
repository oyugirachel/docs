## Overview

The API security scanner probes your live API for common production-readiness and security issues. It runs automatically on `scan api` targets alongside the headers and exposure scanners.

```bash
zenveil scan api https://api.your-app.com
```

ZenVeil makes at most **25 HTTP requests** per scan — only `GET` and conservative `POST` probes with clearly malformed bodies. No data is written or modified.

## Checks

### Rate limiting

**Severity:** MEDIUM · **OWASP:** A04:2021

ZenVeil sends several requests in quick succession and looks for rate-limit response headers (`x-ratelimit-*`, `ratelimit-*`, `retry-after`) or an HTTP 429 response. If neither is detected, the API may be vulnerable to brute-force and credential-stuffing attacks.

**Fix — Express.js (Node.js)**

```bash
npm install express-rate-limit
```

```javascript
const rateLimit = require('express-rate-limit');

app.use(rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100,
  standardHeaders: true,   // sends RateLimit-* headers
  legacyHeaders: false,
}));
```

**Fix — FastAPI (Python)**

```bash
pip install slowapi
```

```python
from slowapi import Limiter
from slowapi.util import get_remote_address

limiter = Limiter(key_func=get_remote_address)
app.state.limiter = limiter

@app.get("/api/users")
@limiter.limit("100/minute")
async def list_users(request: Request): ...
```

### Unauthenticated sensitive endpoints

**Severity:** HIGH (admin/key paths) · MEDIUM (data paths) · **OWASP:** A01:2021

ZenVeil probes paths such as `/api/users`, `/api/payments`, `/api/keys`, `/api/export`, `/graphql`, and others that typically require authentication. An HTTP 200 response without any credentials is flagged as a potential broken access control issue.

**Fix**

Ensure all sensitive routes are protected by server-side authentication middleware — not just the client. Return HTTP 401 for unauthenticated requests.

```javascript
// Express.js — protect all /api/* routes
app.use('/api', requireAuth);

function requireAuth(req, res, next) {
  if (!req.user) return res.status(401).json({ error: 'Unauthorized' });
  next();
}
```

### No request body size limit

**Severity:** LOW · **OWASP:** A04:2021

ZenVeil sends a 10 KB POST body and checks whether the server returns HTTP 413 (Request Entity Too Large). Without a size limit, an attacker can send arbitrarily large payloads to exhaust memory or trigger expensive processing.

**Fix — nginx**

```nginx
client_max_body_size 1m;
```

**Fix — Express.js**

```javascript
app.use(express.json({ limit: '100kb' }));
app.use(express.urlencoded({ extended: true, limit: '100kb' }));
```

**Fix — FastAPI**

Use a middleware or set limits in your ASGI server (e.g. `uvicorn --limit-max-requests`). For body size, check in a dependency:

```python
from fastapi import Request, HTTPException

@app.middleware("http")
async def limit_body_size(request: Request, call_next):
    if int(request.headers.get("content-length", 0)) > 100_000:
        raise HTTPException(413)
    return await call_next(request)
```

### CORS wildcard policy

**Severity:** LOW · **OWASP:** A05:2021

ZenVeil checks whether the API responds with `Access-Control-Allow-Origin: *`. A wildcard CORS policy is acceptable for fully public APIs but may be overly permissive if the API returns any user-specific data. (The HIGH case — wildcard combined with `Access-Control-Allow-Credentials: true` — is detected separately.)

**Fix**

Restrict to known origins instead of using a wildcard:

```javascript
// Express.js
const cors = require('cors');
app.use(cors({ origin: ['https://app.your-domain.com'] }));
```

```python
# FastAPI
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.your-domain.com"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### Missing X-Frame-Options and Permissions-Policy headers

**Severity:** LOW · **OWASP:** A05:2021

ZenVeil checks that the base response includes two headers not covered by the headers scanner:

| Header | Purpose |
|---|---|
| `X-Frame-Options` | Prevents clickjacking by blocking iframe embedding |
| `Permissions-Policy` | Restricts browser features (camera, mic, geolocation) |

**Fix — Express.js (helmet)**

```javascript
const helmet = require('helmet');
app.use(helmet({
  frameguard: { action: 'deny' },
  permittedCrossDomainPolicies: true,
}));
// Add Permissions-Policy manually (helmet doesn't set it by default)
app.use((req, res, next) => {
  res.setHeader('Permissions-Policy', 'camera=(), microphone=(), geolocation=()');
  next();
});
```

**Fix — nginx**

```nginx
add_header X-Frame-Options "DENY" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
```

### Verbose error responses

**Severity:** MEDIUM · **OWASP:** A05:2021

ZenVeil sends intentionally malformed requests (invalid JSON, malformed XML) and scans the response body for stack traces, exception class names, and internal file paths. Verbose errors expose the framework, language, and application structure to attackers.

**Fix — Express.js**

```javascript
// Production error handler — never send stack traces to clients
app.use((err, req, res, next) => {
  console.error(err); // log internally
  res.status(err.status || 500).json({ error: 'Something went wrong' });
});
```

**Fix — FastAPI**

```python
from fastapi.responses import JSONResponse
from fastapi.exceptions import RequestValidationError

@app.exception_handler(Exception)
async def generic_handler(request, exc):
    # log exc internally
    return JSONResponse(status_code=500, content={"error": "Internal server error"})
```

Set `debug=False` in production and ensure your ASGI server does not propagate exceptions to the response body.

### Slow response time

**Severity:** LOW · **OWASP:** A04:2021

ZenVeil measures the wall-clock time of the baseline GET request. A response taking longer than 3 seconds may indicate missing caching, unindexed database queries, or insufficient capacity.

**Common fixes**

- Add a caching layer (Redis, CDN) for frequently read data
- Add indexes on database columns used in `WHERE` and `JOIN` clauses
- Use connection pooling for database connections
- Profile slow endpoints with APM tooling (Datadog, Sentry Performance, Pyroscope)

## Scanner behaviour

| Property | Value |
|---|---|
| Scanner name | `api_security` |
| Target type | `api` |
| Max HTTP probes per scan | 25 |
| Probe timeout | 10 s |
| HTTP methods used | GET, POST (malformed bodies only) |
| Data written to target | None |

ZenVeil never logs request or response bodies, tokens, or credentials — only the host, check name, HTTP status, and response time are written to debug logs.
